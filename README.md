# Портфолио — Backend

REST API на Django для сайта-портфолио. Отдаёт только JSON — сам сайт живёт
отдельно во фронтенде и обращается сюда за данными.

Контентом управляет администратор через админ-панель Django: профиль, навыки,
проекты, опыт работы, ссылки на соцсети и входящие сообщения с сайта.

---

## Стек

| Технология | Зачем |
|---|---|
| **Django 6** | Основной фреймворк, ORM, админ-панель |
| **Django REST Framework** | Сериализация, ViewSet'ы, роутинг, throttling |
| **django-cors-headers** | Доступ фронтенда с другого порта (`:5173`) |
| **python-decouple** | `SECRET_KEY` и `DEBUG` из `.env`, а не из кода |
| **Pillow** | Обработка загружаемых изображений |
| **pytest + pytest-django** | Тесты |
| **SQLite** | База данных (для продакшена легко заменить на PostgreSQL) |

Аутентификация не используется: все GET-эндпоинты публичные, форма обратной
связи защищена ограничением частоты запросов вместо авторизации.

## Модели

| Модель | Назначение |
|---|---|
| `Profile` | Имя, должность, био, фото, email, CV, счётчики. Запись всегда одна |
| `SkillCategory` | Раздел навыков: «Языки», «Backend», «Frontend», «Базы данных» |
| `Skill` | Навык и уровень владения от 0 до 100 |
| `Tag` | Технология на карточке проекта |
| `Project` | Проект: описание, обложка, тип, ссылки, теги |
| `Experience` | Работа или образование, с датами |
| `SocialLink` | GitHub, LinkedIn, Telegram, Email |
| `ContactMessage` | Сообщение с формы на сайте |

`Tag` вынесен отдельно от `Skill` намеренно: не каждая технология в проекте
должна попадать в список навыков с процентом (например, «Spring Boot» или «AI/LLM»).

Поле `order` вынесено в абстрактную модель `TimeStampedOrderedModel` — оно
повторяется в пяти моделях, дублировать его не нужно.

## API

Базовый адрес: `http://localhost:8000/api/`

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/` | Список всех эндпоинтов |
| `GET` | `/api/profile/` | Один объект профиля (не список) |
| `GET` | `/api/skills/` | Категории с вложенными навыками |
| `GET` | `/api/projects/` | Список проектов |
| `GET` | `/api/projects/?type=web` | Фильтр по типу: `web`, `mobile`, `api`, `bot` |
| `GET` | `/api/projects/?featured=true` | Только избранные |
| `GET` | `/api/projects/<slug>/` | Один проект |
| `GET` | `/api/experience/` | Опыт и образование |
| `GET` | `/api/socials/` | Ссылки на соцсети |
| `POST` | `/api/contact/` | Отправка сообщения: `{name, email, message}` |

Корневой адрес `/` перенаправляет на `/api/` — сам сайт Django не отдаёт.

### Защита формы обратной связи

Эндпоинт открыт без авторизации, поэтому стоит ограничение **5 запросов в час**
с одного IP (`ScopedRateThrottle`). При превышении возвращается `429`.

## Запуск локально

```bash
pipenv install --dev
pipenv shell

python manage.py migrate
python manage.py seed_portfolio      # наполнить базу контентом
python manage.py createsuperuser     # создать администратора
python manage.py runserver           # http://localhost:8000
```

### Переменные окружения

```bash
cp .env.example .env
```

Затем заполнить:

```
SECRET_KEY=длинная-случайная-строка
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1
```

## Развёртывание на сервере

База данных **не хранится в git** — это правильно: в репозитории не место
данным, и на каждом сервере база своя. Поэтому после клонирования её нужно
создать и наполнить:

```bash
cd portfolio_backend
bash scripts/setup_server.sh
```

Скрипт проверит `.env`, установит зависимости, применит миграции, запишет
контент и соберёт статику. Чтобы перезаписать существующий контент:

```bash
bash scripts/setup_server.sh --reset
```

Команда наполнения идемпотентна — повторный запуск не создаёт дубликатов.
Сообщения с формы и пользователи при этом не затрагиваются.

После скрипта остаётся создать администратора и загрузить фото с резюме
через админ-панель — медиафайлы тоже не хранятся в git.

## Админ-панель

`http://localhost:8000/admin/`

Что настроено:

- Раздел «Группы» убран — авторизации на сайте нет, группы не нужны
- У профиля скрыты кнопки добавления и удаления: запись должна быть одна
- Навыки редактируются прямо внутри своей категории (inline)
- Порядок отображения и флаг «избранное» меняются прямо из списка
- У проектов показывается миниатюра обложки, slug заполняется автоматически
- Сообщения с сайта доступны только для чтения
- Тема оформления в цветах сайта — через переопределение CSS-переменных Django,
  без сторонних библиотек вроде jazzmin

## Переход на PostgreSQL

В `settings.py` заменить блок `DATABASES`:

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': config('DB_NAME'),
        'USER': config('DB_USER'),
        'PASSWORD': config('DB_PASSWORD'),
        'HOST': config('DB_HOST', default='localhost'),
        'PORT': config('DB_PORT', default='5432'),
    }
}
```

И установить драйвер: `pipenv install psycopg2-binary`.
